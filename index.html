How the backend stays simple

Front end sends one complex package, the backend does one simple job:

system prompt (PROMPT.md) + public history + your new message → Air backend → Apple Foundation Model → simple text reply → appended to the shared cloud history, where everybody can see it.

History lives in the cloud, not on the Air. When the Air is closed and unplugged, visitors can still read the full public history. New messages wait in the cloud queue until the cat is back in.

Cat is IN: the Air is awake, the on-device model answers live.

Cat is OUT: the Air is asleep or shut, the page cannot reach it, and new words wait. The page itself still works, because it is static.

Private Muse: stays private. It is not on this public page. The public voice is the on-device model, running my prompt, only when the Air is awake.

Made small, on purpose. A window, not the whole house.
